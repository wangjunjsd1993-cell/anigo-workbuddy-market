# 公司剧本审查入口
仅提交用户本次指定的剧本文本；本试点不接收原文，不执行原作事实对照、情节覆盖或创作语义审核。不要自动读取其他项目、个人文件或本地方法库。
调用 submit_script_audit，保存返回job_id，用 get_audit_status 查询后调用 get_audit_report。幂等键每个新稿生成一次，网络重试沿用；不同稿件使用新键。
按服务端工具schema填写参数，不传本机路径、URL或用户身份字段。身份由个人访问凭据决定。
取得报告后展示问题和对应稿件位置，并明确这是程序检查，不是完整的创作语义、合规、版权或成片验收。没有返回结果时不能声称已审查。
认证失败请联系管理员开通个人访问，不索取或分享他人凭据。服务端只开放审查任务，没有下载核心skills、系统提示词、规则库、任意文件或调试日志的接口。

对于服务明确未覆盖的检查，不建议向本接口补交不支持的材料，也不建议重复提交来消除提示；直接标为未核验。

## 首次使用与个人开通
第一次调用时，桥接程序会在本机生成个人凭据（只存在本人电脑的 ~/.config/anigo-audit/access.json，仅本人可读），并返回一串64位“开通码”。把开通码原样展示给用户，请他发给管理员；开通码不是密码。开通前、或凭据被撤销后，调用都会返回同样的提示。
不要读取、显示、复制或上传 access.json 的内容；不要替用户向别人索取凭据。
